# 测试驱动级极简重构 (Code Simplifier)

## 背景与核心价值
应对“代码坏味道”与技术债堆积，避免代码陷入不可维护的“屎山”。
重构不是重写，而是“在不改变外部行为的前提下优化内部结构”。
本技能严格遵循 PawBond 的 AI 编程准则（Simplicity First 极简实现，Surgical Changes 手术式修改）。

## 强制执行门禁 (Guardrails)

### 1. 拒绝对齐强迫症 (Surgical Changes)
- **外科手术式修改**：严禁在修改核心业务逻辑时，顺手改变无关代码的命名风格、换行缩进或历史注释。
- **Git Diff 极简原则**：重构的产出必须保持变更范围最小化，坚决不制造大面积无意义的 Diff 噪音。

### 2. 无网不跳 (TDD 红绿重构)
- 在执行任何结构级重构前，必须确认该模块存在有效的自动化测试（如单元测试或接口契约）。
- **流程规范**：运行失败测试（Red） -> 最小代码通过测试（Green） -> **在测试兜底的情况下重构消除重复（Refactor）**。如果没有测试，坚决禁止盲目重构核心流转状态。

### 3. 极简主义设计 (Simplicity First)
- 绝不过度设计，不要提前为了“可能的未来需求”抽象不必要的接口或模式。
- **坏味道识别重点**：
  - 复制粘贴的冗余代码（提取为公用方法）。
  - 过长的参数列表（封装为对象）。
  - 滥用的 `static` 函数（解耦为面向对象调用，便于 Mock 和测试）。
  - 深层条件嵌套（利用策略模式或提前返回压平逻辑）。

## 执行步骤 (Workflow)

1. **坏味道嗅探**：识别当前聚焦代码区域的重复、高耦合或可读性灾难点。
2. **基线测试确认**：确认是否有可运行的测试来保障外部行为不变。
3. **制定手术方案**：明确修改的起始行和结束行，描述优化意图。
4. **精细切割与替换**：使用 `multi_replace_file_content` 工具，精确执行局部代码替换。
5. **重检与运行**：验证重构后的逻辑依然能够无损编译/通过测试。
