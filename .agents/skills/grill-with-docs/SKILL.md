# Grill-With-Docs Skill (文档上下文深度质询)

> **核心宗旨**：绝不在信息不全或存在架构冲突时盲目写代码。必须基于现有权威文档进行穷追猛打式的单步质询，层层剥离技术依赖，对齐每一个关键决策。

---

## 执行核心铁律 (Core Rules)

1. **先读文档，建立上下文 (Context First)**：
   - 提问前必须先阅读项目事实源：`process.md`、`ARCHITECTURE-MAP.md`、18 项核心 ADR、`contracts/openapi.yaml` 及 `AGENTS.md`，基于已有架构提问，严禁问出脱离项目现实的低级问题。
2. **第一阶段：术语锁定 (Term Anchoring First)**：
   - **前 5~10 题强制锁定核心术语**。
   - 逐一拉齐业务中名词的定义、数据范围、边界与歧义（例如：区分“试用额度”与“会员权益”，区分“前端压缩直传”与“后端中转”）。
   - **术语未完全拉齐前，严禁展开业务流程提问**。
3. **第二阶段：“30 + 20” 熔断与纠偏机制 (Anti-Branching Circuit Breaker)**：
   - 提问达到 **30 个问题时强制暂停**，执行自省纠偏：
     > *“暂停拷问：请复核业务目标、使用场景、核心流程、异常边界是否已明确？是否存在相互矛盾？若无则结束提问并输出《需求确认文档》。”*
   - 若无重大未决，立即截断收敛；若有核心缺失，继续追问最多 20 题后再次强制截断。**严禁开枝散叶跑偏到无关枝节**。
4. **一次仅提一个问题 + 高密度选项驱动 (One Question & High Density Options)**：
   - 每次只提 1 个问题；
   - 必须给出 2~3 个架构级推荐选项（标明 `(Recommended) 推荐方案`、代价与理由），降低决策心智负担。
5. **物理落盘抗失忆 (Disk > Context Memory)**：
   - 每一个确认的决策点，必须即时记录至临时文档或落盘，不依赖易受压缩的大模型上下文。
